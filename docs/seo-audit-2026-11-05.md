# Live discoverability audit — November 5, 2026

Scope: read-only live HTTP inspection, repository metadata review, public search queries, and public GitHub profile inspection. No production changes or form submissions.

## Overall result

The deployed Astro site is reachable and serves readable HTML without requiring JavaScript. Discovery needs attention, particularly a conflicting homepage canonical, missing sitemap, and the empty website field on the public GitHub profile. Actual Google index inclusion remains unverified without Search Console.

## Confirmed observations

- HTTPS homepage, about, projects, résumé, contact, and four sampled case studies return 200. The deployed homepage includes Leakline and Infrastructure Automation Lab, confirming the updated content is live.
- Sampled content pages have unique titles/descriptions, one H1, normal HTML links, and no robots meta noindex or X-Robots-Tag restriction.
- Homepage canonical and og:url are generated from an index path. The canonical is https://cybersteveon.dev/index while /index and /index.html return 307 redirects to /. Fix the layout normalization so the homepage explicitly declares https://cybersteveon.dev/. This defect originated in the migration layout.
- Other sampled content-page canonicals match their clean URLs.
- /sitemap.xml and /sitemap-index.xml return 404. No sitemap implementation exists in the inspected repository.
- /robots.txt returns 200 text/plain with content-signal explanatory comments only. The observed body contains no User-agent, Disallow, or Sitemap directives. No conventional crawl prohibition was observed. This response exists at the hosting layer despite the lack of a repository file; account configuration was not inspected.
- A nonexistent URL returns a real 404. However /404 itself returns 200 and lacks noindex. Add noindex to the error template and exclude it from the sitemap; retain actual 404 statuses for missing URLs.
- Direct HTTP requests return 200 without redirecting to HTTPS. Consider enabling an HTTP-to-HTTPS permanent redirect at Cloudflare. Browser HTTPS behavior for .dev must not be used as proof that the server redirects.
- www.cybersteveon.dev does not resolve from the audit host. Optional: configure a www alias and redirect it to the existing apex site. This is not required for indexing the functioning apex domain.
- Social preview PNG and résumé PDF return 200. Sampled pages have Open Graph metadata. No JSON-LD or twitter:card was observed. These are enhancements, not prerequisites for indexing.
- Public GitHub API reports empty name, website/blog, and bio fields for CyberSteveon. Add the public name, portfolio URL, and a concise professional bio to improve the path from code to portfolio.
- Searches for site:cybersteveon.dev and the combined quoted name/handle returned no results in the available search tool. This is a visibility signal, not proof of exclusion from Google or any other specific index. The search tool could not retrieve the site, while direct HTTPS requests succeeded; its fetch failure is not evidence of a general outage or Googlebot block.

## Recommended sequence

1. Correct homepage canonical/og:url and add regression checks for their exact expected values.
2. Generate a sitemap with the 12 real content pages (five main pages and seven case studies), excluding 404 and API paths. Reference it from a robots.txt response while accounting for hosting-managed content policy.
3. Add noindex to the 404 template.
4. Verify ownership in Google Search Console, inspect the homepage and project URLs, submit the sitemap, and request indexing after approved deployment. Do not infer property ownership or indexing from repository files.
5. Add the site to GitHub's website field and ensure LinkedIn and application materials provide direct links. LinkedIn profile placement was not verified in this audit.
6. Review Cloudflare HTTPS redirection; optionally add www forwarding. No DNS changes were made.
7. Optionally add factual Person/ProfilePage structured data on About, using the public name, handle, and profile links. Add an explicit social card tag. Neither guarantees rankings or rich results.

## Limits

No Search Console, Cloudflare dashboard, real Googlebot request, Lighthouse run, field Core Web Vitals report, backlink inventory, or recruiter-identity analytics was available in this audit. HTML payload sizes are modest (roughly 6–20 KB for sampled content pages) but this is not a performance score. No indexing, ranking, or delivery guarantees are made.
